# PiggyPulse iOS v2 — Implementation Plan

> Port the v2 web redesign to iOS. Every feature from the web must be present on iOS, but the UI must follow HIG and feel native-iOS-first. Functionality matches; visual design may differ.

## Constraints

1. **HIG always wins.** Every screen, component, and interaction must follow Apple's Human Interface Guidelines. If HIG conflicts with the web design, HIG takes precedence.
2. **Native iOS patterns.** SF Symbols, swipe actions, contextual menus, search integration, pull-to-refresh, haptic feedback, system materials/vibrancy — use them all where appropriate.
3. **Same functionality, different presentation.** The web and iOS apps must offer the same features, but the iOS app should feel like it was designed for iOS from scratch.
4. **6 color themes.** Nebula, Sunrise, Sage & Stone, Deep Ocean, Warm Rose, Moonlit — each with dark + light mode. Adapt colors to feel native using system materials and vibrancy.
5. **Full i18n.** Every user-facing string must be translatable (en + pt-BR). Use Xcode String Catalogs.
6. **iOS 26 tab bar.** Transparent frost glass tab bar on all tabs.
7. **Biometrics & notifications stay as-is.** No changes to existing Face ID/Touch ID or background notification features.
8. **Overlays preserved but hidden.** Keep overlay code for later; subscriptions is a new, separate feature.
9. **Deployment target:** iOS 26.2 (unchanged).
10. **No third-party dependencies.** Continue using only Apple frameworks.

## Navigation Architecture

### Tab Bar (4 tabs, frost glass, iOS 26 style)

| Tab | Icon (SF Symbol) | Destination |
|-----|-------------------|-------------|
| Dashboard | `house.fill` | Dashboard screen |
| Transactions | `arrow.left.arrow.right` | Transactions list |
| Accounts | `creditcard.fill` | Accounts list |
| More | `ellipsis.circle` | Hub screen |

### More Tab — Grouped Sections

| Section | Items |
|---------|-------|
| **Planning** | Periods, Categories, Targets |
| **Tracking** | Subscriptions, Vendors |
| **App** | Settings |

Each item navigates via `NavigationStack`. The More tab uses a `List` with section headers matching these labels.

### Period Selector — Alternatives to Evaluate

The period selector defines which budget period is active across the app. Currently lives in the tab bar sidecar (bottom accessory). Discoverability is a concern.

**Alternatives to prototype and evaluate:**

| # | Approach | Placement | Pros | Cons |
|---|----------|-----------|------|------|
| A | **Tab bar sidecar** (current) | `tabViewBottomAccessory` | Persistent, always visible | Easy to miss; users may not understand what it is |
| B | **Navigation bar title** | `toolbar(.principal)` | Familiar (Messages-style picker); always visible on every screen | Takes nav bar space; needs compact design |
| C | **Floating pill** | Overlay pinned above tab bar | Eye-catching; tappable | Can overlap content; non-standard |
| D | **Inline banner** | Top of each page content | Contextual; impossible to miss | Pushes content down; repetitive |
| E | **Sidecar with label** | Current sidecar + descriptive label/icon | Minimal change; better affordance | May still be missed |

**Decision:** Prototype at least A (improved) and B during the architecture phase. Pick one before feature work begins.

### iOS Adaptation

- Use `Color(uiColor:)` with dynamic trait collections for dark/light switching
- Apply system materials (`.ultraThinMaterial`, `.regularMaterial`) for frost glass effects on cards and overlays where appropriate
- Use `ShapeStyle` and `.tint()` modifiers to apply theme accent colors to system components
- Store selected theme in UserDefaults; expose via `@Observable` ThemeManager injected through `.environment()`

## Dashboard Widgets

The web v2 dashboard has customizable widgets. iOS should offer the same set, adapted to native patterns.

### Widget Set

| Widget ID | Name | Description | Default visible |
|-----------|------|-------------|-----------------|
| `getting_started` | Getting Started | Setup checklist (TipKit-based) | Yes (auto-hides) |
| `current_period` | Current Period | Budget progress for active period | Yes |
| `net_position` | Net Position | Total across all accounts | Yes |
| `cash_flow` | Cash Flow | Inflows vs outflows | Yes |
| `recent_transactions` | Recent Transactions | Latest activity | Yes |
| `spending_trend` | Spending Trend | Spend over time | No |
| `top_vendors` | Top Vendors | Where money goes | No |
| `variable_categories` | Variable Categories | Discretionary spending | Yes |
| `fixed_categories` | Fixed Categories | Predictable expenses | No |
| `subscriptions` | Subscriptions | Recurring charges | No |
| Account cards | Per-account | Individual account balance | No |

### Customization

- Long-press dashboard to enter edit mode (iOS home screen-style jiggle/reorder)
- Drag to reorder, remove button (−) on each widget, "+" button to add hidden widgets
- Persist layout in UserDefaults (same structure as web preferences: `widgetOrder`, `hiddenWidgets`)

## New User Guidance (adapted to iOS)

### Empty States
- Use a consistent `EmptyStateView` component across all list screens
- Include: SF Symbol icon, title, description, numbered steps, tips, and a primary action button
- Same content as web (translated), adapted visually to iOS cards

### Contextual Hints (TipKit)
- Replace the web's `PageHint` banners with Apple's **TipKit** framework
- One tip per screen explaining what the page is for
- Tips auto-dismiss after interaction or can be manually dismissed
- TipKit handles persistence, frequency, and display rules natively

### Getting Started Checklist
- Dashboard widget (not a TipKit tip — it's interactive)
- 4 steps: Create account, Set up period, Configure categories, Add first transaction
- Each step links to the relevant screen
- Auto-hides when all steps complete; manually dismissible via close button
- Adapt the card style to iOS (SF Symbols for checkmarks, native list styling)

---

## No Period State

- Consistent `NoPeriodStateView` shown on all screens except Periods when no period is selected
- Calendar icon (SF Symbol `calendar.badge.exclamationmark`), clear title, description, and "Go to Periods" button
- Replaces the previous inline dimmed text approach

## Subscriptions (new feature)

Port the web v2 subscriptions feature:
- **List screen:** Active, paused, and cancelled sections; collapsible cancelled group
- **Stats bar:** Monthly cost, yearly total, active count, next charge
- **Upcoming charges:** Timeline view showing next 5 charges with dates and amounts
- **Add/Edit sheet:** Name, vendor, category, billing amount, billing cycle (monthly/quarterly/yearly), next charge date, status
- **Cancel flow:** Cancel modal with cancellation date and reason
- **Detail screen:** Full subscription info with billing history
- Accessible from More > Tracking > Subscriptions
